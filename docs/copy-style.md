# Cairn 文案与术语规范

界面文案的唯一规范来源。写任何用户可见的 UI 文字（按钮、标题、描述、空态、报错、tooltip、浮窗脚本、报错 toast）之前先读这一页；AI 辅助开发时把这一页喂给模型。规则来自 0.3.1 产品经理文案审查（背景：产品在跟用户讲自己的实现，界面像「仪表盘后面贴满工程图纸」）。

## 总原则

1. **界面是汽车仪表盘，不是工程图纸。** 用户关心「这笔交易怎么样」，不关心数据结构。不解释 UI 自己（“核心状态与组成，一屏可见”这类给评审看的句子直接删）。
2. **计算口径说明挂 ⓘ（`components/info-hint.tsx`），不常驻占位。** 用户第一次需要它，第一百次不需要。R 口径、计划 vs 实际来源、过程分哲学、AI 原则宣言都是这么处理的。正面示范：交易表 PnL% 的 tooltip。
3. **原则/价值观类文案只出现一次。** “只摆事实，不打分——过程评价永远是你自己的”这类话放 tooltip 或首次引导，不要每次渲染。
4. **同一事实只在一处说全。** 侧栏是扫一眼的大数字，细节活在对应 tab；状态 badge 和只读文本不重复出现。
5. **空态要么给下一步动作，要么不渲染。** 不为“没有东西”画一张大卡。

## 中英规则

- **领域词保留英文**：BAR、R、PnL、Case、Card、Trade、Period、Execution、Profit Factor、EMA、UTC、JSON、memo（Entry 卡语境）。这些是交易者词汇，翻译反而增加认知负担。
- **UI 结构词必须中文**：时间线、轨迹线、入场线、根（K 线）、复盘/案例/评估 tab、元信息。
- 一个词要么一直中文要么一直英文，同一屏不混用两种风格。

## 保留的品牌调性

- 「心路历程」是刻意的品牌语言，保留；同语气的新功能命名保持这种温度（卡片阶段提示语「这张卡可以覆盖：…」同属此类）。
- AI 功能的动词保持「秘书感」：AI 识别、AI 找 Case / AI 找 Trade、AI 拟题、AI 总结、AI 补录建议——都是「替用户干活」，不是「展示智能」。

## 数值与格式

- 金额单行放不下用 `fmtCompactMoney`（≥1 万 K/M/B），完整值放 title 悬停；不要让统计卡换行。
- 报错文案 = 一句人话 + 下一步。技术原因（网络/解析/Provider 配置）进日志（Rust `log_provider_event` / 前端日志），不糊用户脸上。

## 变更纪律

- 改任何用户可见文案时同步检查本页术语表；新增术语先在这里登记再用。
- 浮窗脚本 `scripts/cairn-case-widget.user.js` 的文案同受本页约束（改脚本记得 bump `@version`）。
