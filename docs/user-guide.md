# Cairn 使用教程

本教程面向新用户，覆盖从零安装配置到日常使用的完整流程，基于 0.2.0 版本撰写，随版本更新维护。

Cairn 是一个本地优先（local-first）的交易日志与复盘工具：所有数据存在你自己的电脑上（本地 SQLite），不需要联网注册，未来也不会做实时云同步。它的核心用法是：**盘中在 TradingView 上随手记录思考 → 盘后导入成交 → AI 帮你整理 → 用数据复盘**。

## 核心概念速览

| 概念 | 含义 |
| --- | --- |
| **Account（账户）** | 一个交易账户，分「实盘」和「回测」两类，两者共用同一套模型。 |
| **Period（周期）** | 账户下的时间段（比如「2026 年 8 月」），用来分组交易和统计数据。 |
| **品种（Symbol）** | 交易的标的（如 BTCUSDT 期货）。在设置页维护。 |
| **Execution** | 一条交易动作记录。分两类：**仓位变动**（Entry / Scale in / Scale out / Exit）和**管理动作**（Move stop / Move target / Add / edit order）。只有仓位变动 Execution 参与盈亏、均价、R 等指标计算；管理动作只出现在时间线和图表上。 |
| **Trade（交易）** | 由一组 Execution 归组而成的一笔完整交易（含多次加仓减仓）。 |
| **Case（案例）** | 围绕一笔潜在交易的**连续推理记录**——从观察到入场到离场的思考过程。Case 可以在交易发生之前就创建（纯观察没下手的 Case 也保留为观察记录）。一个「记录中」的 Case 最多绑定一个 Trade。 |
| **CaseCard（卡片）** | Case 里的一条原始记录（语音转文字或打字）。按五个阶段分类，原文永久保留。 |
| **Note（笔记）** | Markdown 笔记，可以在文中 `@` 引用某笔交易或图片。 |

页面导航（左侧边栏）：**仪表盘 / 账户 / 交易 / 案例 / 数据 / 笔记 / 导入 / 设置**。

## 首次准备：账户、品种与设置

按下面的顺序做一遍，后面所有功能就都可用了。

### 1. 创建 Account 和 Period

1. 打开「**账户**」页，点新建账户：填写名称、选择类型（实盘 / 回测）、初始资金、货币。
2. 点进刚建的账户，新建 Period：名称（如「8 月第一周」）、图表开始 / 结束时间（用于对齐图表数据范围）。

### 2. 创建品种

1. 打开「**设置**」→「**数据**」标签 → 品种卡片，点新建。
2. 填写交易所、代码、名称、类别（加密货币 / 外汇 / 期货 / 股票）和价格精度。

### 3. 本地 API（为油猴脚本做准备）

打开「**设置**」→「**本地 API**」标签。默认情况下本地 API **已经启用**，无需手动开启：

- **运行状态**应显示绿点「运行中 · 127.0.0.1:8787」。服务只监听本机（127.0.0.1），不会暴露到网络；服务随应用常驻（最小化到托盘也在运行），关闭窗口不影响。
- 点「**复制 Token**」，把访问 Token 复制到剪贴板——第 3 节安装油猴脚本时要粘贴它。
- 端口默认 8787。如果被占用可以改，但**修改后需要重启应用**才生效；启动失败原因可在「设置 → 日志」里查看。
- 「重新生成」会作废旧 Token：生成后记得去脚本设置里更新，否则脚本会提示 Token 无效。

### 4. AI Provider（为 AI 整理做准备）

打开「**设置**」→「**AI**」标签 → 点「**添加 Provider**」：

1. 点一个预设（OpenAI、Anthropic、OpenRouter、Gemini、Groq、DeepSeek、智谱 GLM、Kimi、通义千问、硅基流动、Ollama、自定义），Base URL 会自动填好。
2. 填 API Key（本地运行的 Ollama 等无鉴权服务可留空）。
3. 点「**获取模型**」拉取模型列表，从下拉里选默认模型（拉取成功即代表连接正常）。
4. 打开「**设为默认 Provider**」开关，保存。

所有 AI 功能（卡片整理、拟题）只使用**默认** Provider。API Key 只保存在本机，不会进入备份文件。

## 安装与配置油猴脚本（TradingView 悬浮窗）

悬浮窗（右下角「记一笔」圆球）是盘中记录 Case 的主要入口，它通过 Cairn 的本地 API 把卡片直接写进主程序。安装一次性完成，之后打开 TradingView 就常驻。

### 前提

- Cairn 桌面版**正在运行**（托盘常驻即可），本地 API 状态为「运行中」。
- 浏览器（Chrome / Edge / Firefox 均可）已安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展。

### 安装脚本

1. 找到脚本文件：仓库中的 `scripts/cairn-case-widget.user.js`（名字是「Cairn 记一笔」），用任意编辑器打开，**全选复制**文件内容。
2. 点浏览器工具栏的 Tampermonkey 图标 → 「管理面板」，再点左上角「**＋**」（添加新脚本）。
3. 删掉编辑器里的模板代码，**粘贴**刚才复制的全部内容。
4. `Ctrl + S` 保存。脚本会自动匹配 `https://*.tradingview.com/*`，只在 TradingView 页面生效。

### 首次连接配置

1. 打开 TradingView 任意图表页，页面右下角出现蓝色「✎ 记一笔」悬浮球（可以**拖动**到顺手的位置，位置会记住）。
2. 第一次点击悬浮球会自动弹出连接设置：把「设置 → 本地 API → 复制 Token」得到的 Token 粘贴进 **API Token** 输入框；端口保持 **8787**（除非你在主程序里改过）。
3. 点「**保存并连接**」，状态行出现「✓ 已连接」即成功。之后 Token、端口、当前 Case、阶段、悬浮球位置都会自动记住，不用再管。

### 连不上的排查

| 现象 | 原因与处理 |
| --- | --- |
| 「Token 无效」 | 回设置页重新复制 Token 粘贴；如果你点过「重新生成」，旧 Token 已作废，必须更新脚本里的。 |
| 「无法连接 127.0.0.1:8787」 | Cairn 没在运行（看托盘）；或主程序改过端口但还没重启；或端口被占用（设置 → 日志 看原因，换端口后两边保持一致）。 |

### 不装 Tampermonkey 先体验一遍

仓库里的 `scripts/cairn-case-widget.test.html` 是免安装测试页：保持 Cairn 运行，用浏览器直接打开这个文件，就能看到和 TradingView 上完全一样的悬浮球（Token 同样从设置页复制，在测试页的设置里粘贴一次）。

### 可选：Bar Count 指标

卡片可以标注「第几根 K 线」（BAR №）。配套的 Pine 指标 `scripts/cairn-bar-count.pine` 会在 TradingView 图表的每根 K 线上标注序号（约定：UTC 00:00 开盘的第一根 K 线为 1，逐根 +1），这样口述「BAR38」时图表上有对应数字可对照。在 TradingView 的 Pine Editor 里粘贴该文件内容并「添加到图表」即可。

## 盘中记录 Case

### Case 的节奏

一个 Case 覆盖「上一笔交易结束 → 下一笔交易执行完成」这一段：先以「观察」开 Case，想到什么记什么；决定入场就记「入场」卡；持仓中有变化记「过程」卡；离场记「离场」卡；盘后写「复盘」卡。没下手就放弃的观察 Case 也同样保留。

### 悬浮窗操作

1. **开新 Case**：点面板头部的「＋」，选好账户和 Period（会记住上次选择），标题可留空（自动按「品种 观察 时间」生成，之后可用 AI 拟题改写），点「创建并切换」。
2. **切换 Case**：点面板头部的 Case 标题，弹出最近的 Case 菜单。日常只在一个「当前 Case」上连续记录，切换是按需操作。
3. **选阶段**：五个彩色阶段 pill——**观察 / 入场 / 过程 / 离场 / 复盘**。每个阶段下方有一行灰字检查单提示这张卡可以覆盖什么（入场卡对应六字段：方向、止损、目标、置信度、失效条件、放弃的方案）。
4. **记录**：在文本框里打字（或语音转文字粘贴），可选填 **BAR №**（不填则自动从原文里提取「BAR38」「第 42 根 K 线」这类写法），`Ctrl/Cmd + Enter` 提交。
5. **入场卡**额外要选执行情况：**待确认 / 已执行 / 未执行·继续观察**。提交后如果没提到失效条件、目标或方向，会弹黄色提示「还没提到：…」，可补一张卡。
6. 面板下半部是当前 Case 的卡片时间线，主程序界面也会近实时刷新出新卡片。

### 卡片的两条铁律

- **原文永久保留**：AI 和解析结果永远不会改写你的原文；发现自己打错字可以在主程序 Case 详情页修正，旧版本自动存入历史记录。
- **错卡可修**：卡记到错误的 Case 里，可以在 Case 详情页把它移动到正确的 Case，只有归属变化，原文不动。

## 导入 TradingView 交易

打开「**导入**」页，固定四步：**选择归属 → 上传文件 → 归组预览 → 完成**。

1. **选择归属**：选 Account + Period + 品种，这批交易全部归入该组合（所以要先建好账户、Period 和品种）。
2. **上传文件**：TradingView 交易导出必传；图表数据（CSV/Excel）和参考图可选。
3. **归组预览**：逐笔 Execution 勾选导入，预览会警告归组问题（如没有匹配仓位的离场）。导入不会覆盖已有交易，重复数据不会重复入库。
4. **完成**：显示导入结果。如果导入前你已经在记 Case，这一页还会出现 **Case 关联**：

| 指示 | 含义 | 动作 |
| --- | --- | --- |
| 🟢 绿球 | 精确匹配：入场时间与「已执行」入场卡、离场时间与离场卡都在 ±15 分钟内 | 已自动绑定，无需操作 |
| 🟡 黄球 | 部分匹配或多个候选（只有入场对得上、或卡片只是落在交易前后一小时内） | 人工确认后一键绑定 |
| 🔴 红球 | 没找到任何候选 Case | 「漏记录」的可见提醒，不需要处理 |

注意：Case 匹配只按**账户 + 时间窗**进行（Case 本身不记录品种），所以确认黄球时请核对一下交易和 Case 的品种是否一致。「撤销本次导入」会连同这次自动建立的绑定一起回滚。

## 复盘与整理

### Case 详情页（案例 → 点进某个 Case）

- **AI 整理**：每张卡右上角的星花按钮，把原文结构化——在原文上画出彩色标签（市场背景、形态条件、入场计划、失效条件……），入场卡额外提取六字段 memo（方向渲染为彩色做多/做空），并机械推导出**缺失字段检查单**（不信任模型自报，缺什么算什么）。
- **全部 AI 整理**：「心路历程」卡头部按钮，逐张跑完整个 Case。
- **带要求重试**：分析落款行里的小链接，弹出的输入框里写一句修正要求（如「止损不是 41650，注意口语里的位置词」），随重试一起发送。重跑会替换旧分析，永远不动原文。原文改过错字后旧分析会标记「已过期」，建议重跑。
- **AI 拟题**：标题旁的按钮，读全部卡片后代拟一个 ≤20 字的标题。
- **移动卡片 / 绑定状态**：错卡移动到别的 Case；侧栏显示与 Trade 的绑定情况，可跳转。

### Trade 详情页（交易 → 点进某笔交易）

三个标签：

- **Overview**：复盘图表（Trail line、Entry line、Zones 叠加，绑定 Case 的卡片会以 BAR 标记出现在图上）、合并时间线（Executions + Case 卡片）、配图、结果侧栏。
- **Case**：绑定管理——选一个空闲 Case 绑定、新建并绑定、或解除后重绑（一个 Case 只能绑一笔交易，反之亦然）。
- **Trade**：数字分析，见下。

### Trade 标签里的四张卡

1. **结果事实**：PnL、R 倍数、Execution 数、持仓时长。结果只记录，不参与过程评分。
2. **风险分解**：**R（初始风险）** = 盈亏 ÷ 初始风险（首笔入场价 − 初始止损 × 首笔数量，加仓不会稀释分母）；**R 实际风险** = 盈亏 ÷ 实际风险（每笔加仓按当时生效的止损分段累加，放宽过止损在这里现形）。两个 R 并列展示，不作判断。
3. **计划 vs 实际**：计划方向/止损/目标（来自绑定 Case 的入场卡 memo）对阵实际方向、最终止损、平均离场，只摆事实。
4. **过程分（十分制）**：只使用**决策时点**的信息——机械项（memo 完整性、计划盈亏比、止损是否只收紧）自动推导，判断项（结构成立、入场纪律、出场按计划、临时动作数）人工打分。R 永远不进过程分，防止「以结果论过程」。

### Case 自动收尾

Case 在「记录中」时满足任一条件会自动转为「已完成」：

- 绑定的 Trade 已完全平仓，**且**写了离场卡（复盘卡可以后补，不阻塞）；
- 没有绑定任何交易（纯观察 Case），**且**写了复盘卡。

故意留的口子：Trade 平仓了但还没写离场卡的 Case 会保持「记录中」——开着的 Case 就是提醒你补离场记录。你手动改过的状态永远优先，不会被再次自动翻转。

### 手动补录 / 新建交易

「交易 → 新建」或在交易详情点「编辑」，可以手工补 Execution：

- **Move stop**：止损价变更（第一次 Move stop 即建立初始止损）。手动移动止损就用它表达，追踪行为通过 Reason（如 Trail / protect profit）说明，不另设订单类型。
- **Move target**：止盈价变更。
- **Add / edit order**：普通挂单的创建或修改（限价 / 止损 / 止损限价），不要用它记正常的止损止盈移动。

仓位变动类（Entry / Scale in / Scale out / Exit）才影响盈亏和指标。

## 分析

Cairn 没有单独的「分析」页，绩效分布在三个层级：

- **仪表盘**（首页）：总权益、胜率、最大回撤、权益曲线、各账户概况。
- **账户详情 / Period 详情**：当前权益、交易数与胜率、期望值/笔、最大回撤、权益曲线、Period 概况、交易表。
- **交易列表**：高级筛选——快捷开关（未评分、出场偏离计划、放宽止损、缺初始止损）、R 与过程分区间筛选、可保存的筛选预设。

所有指标都由仓位变动 Execution 推导，与交易的状态标签无关。

## 笔记与数据管理

### 笔记

「**笔记**」页新建 Markdown 笔记，编辑时键入 `@` 可以引用某笔交易或图片（保存为 `[[trade:ID]]` / `[[image:…]]`）；交易详情页会反向列出提及它的笔记。

### 图表数据

「**数据**」页管理图表数据：导入 CSV/Excel（手动选择 K 线周期：5m / 15m / 1h / 4h / 1d）、覆盖度检查（缺口、缺数据的交易）、原始文件归档、「规范数据」（同品种 × 周期合并去重，可导出）。重复导入同一份数据不会产生重复 K 线。

### 备份与恢复

「**设置 → 数据**」→ 备份卡片：手动备份导出 JSON 到应用数据目录的 `backups/`；每天首次启动自动备份到 `backups/auto/` 并保留最近 7 份。**恢复会整体替换本地数据**，AI 的 API Key 不在备份范围内，恢复后如换机器需要重配。

## 常见问题

**Q：关掉 Cairn 窗口后悬浮球还能用吗？**
关闭窗口是隐藏到托盘，不是退出——本地 API 随托盘常驻，悬浮球照常工作。彻底退出（托盘右键退出）后悬浮球会提示无法连接。

**Q：为什么必须装 Tampermonkey，不能用普通书签脚本？**
TradingView 是 HTTPS 页面，浏览器禁止它直接请求本地 HTTP 服务（混合内容拦截）。Tampermonkey 的 `GM_xmlhttpRequest` 可以跨过这个限制，且只允许连接 127.0.0.1/localhost。

**Q：AI 按钮点了没反应 / 报错？**
确认两件事：AI 功能只在桌面版里可用（浏览器开发模式不行）；设置 → AI 里已配置且**设为默认**的 Provider 能拉到模型列表。

**Q：我的交易数据存在哪里？安全吗？**
全部在本机：SQLite 数据库和备份都在系统的应用数据目录里，不上传任何服务器。本地 API 只监听 127.0.0.1 且需要 Token，外部机器无法访问。

**Q：重新生成了 Token，脚本提示 Token 无效？**
旧 Token 已作废。点悬浮球面板的 ⚙（或 Tampermonkey 菜单里的「Cairn 连接设置」）重新粘贴新 Token。

**Q：Case 跨天了，两天都会出现 BAR38，会不会冲突？**
不会。BAR 序号每天 UTC 00:00 重置，卡片本身带真实时间戳，数据层面不会冲突。复盘图表和时间线按**创建顺序**机械还原位置：后创建的卡片一定不早于前一张，序号比前面小会被自动解释为跨到了下一天，序号相同视为同一根 K 线——不需要也不允许手动指定是哪一天。
